# HAVN web (storefront)

Next.js 15 App Router skeleton for the HAVN storefront: a bilingual
(繁體中文 + English) designer-homeware ecommerce flagship for Hong Kong.
Front end only; the Rust API lives in `../api/`.

Authoritative vision: `../Vision.md` (this repo root). Visual register:
`../docs/designs/havn-opening-drop.md` ("Frontend Design Direction").

## Stack

## Commands

| Command | What it does |
| --- | --- |
| `npm ci` | Clean-clone / CI install from the lockfile (use this, not `npm install`, for reproducible builds). |
| `npm install` | Install pinned dependencies. |
| `npm run dev` | Dev server. |
| `npm run build` | Production build; statically generates `/en` and `/zh-HK`. |
| `npm run start` | Serve the production build. |
| `npm run lint` | ESLint, flat config (`eslint.config.mjs`), `next/core-web-vitals` + `next/typescript`. |
| `npm run typecheck` | `tsc --noEmit` (strict). |
| `npm run test` | `node --test "test/*.test.mjs"`: behavioral route tests against a spawned production server, plus pure unit tests for the data layer. The route suite requires a prior `npm run build`; the unit tests do not. |

Note: `tsc` reads Next's generated types from `.next/types`. Run
`npm run build` once after changing route/layout files if `typecheck` reports
stale generated-type errors.

Build-time network dependency: `next/font/google` downloads the four font
families from fonts.googleapis.com on an uncached build. An offline machine
that has never built before cannot build; CI caches `node_modules` but the
font cache lives in `.next/cache`.

## Locale routing

- Routes are `/en` and `/zh-HK`, generated by `generateStaticParams()` in
  `app/[lang]/layout.tsx` with `dynamicParams = false`.
- The root layout is `app/[lang]/layout.tsx`: it is the only place that can
  set `<html lang>` (`en` or `zh-Hant-HK`) without middleware. A root
  `app/layout.tsx` cannot see `[lang]` params (verified: it receives `{}`),
  which is why there is none.
- Anything else (unknown locale, unknown subpath, `/`) returns HTTP 404 from
  `app/global-not-found.tsx` (Next 15 `experimental.globalNotFound`): the bare
  shell owns `<html lang="en">` (documented default, `lib/i18n.ts
  defaultLocale`) and renders bilingual 404 content at equal weight with
  `lang` on each passage. A locale-scoped catch-all was rejected because
  `notFound()` thrown at request time escapes SSR in this no-root-layout
  setup and the recovered document loses its `lang` attribute.
- `app/not-found.tsx` and `app/[lang]/not-found.tsx` remain as safety-net
  boundaries sharing the same content component; they are unreachable under
  the current static allowlist and therefore not exercised by `npm run test`
  (which covers the locale pages and the global shell).

## Type and colour tokens

`app/globals.css` (Tailwind v4 `@theme`):

- Warm neutrals: `bone` `#f7f3ec`, `ecru`, `sand`, `linen`.
- Text: `charcoal` `#22201c` (14.7:1 on bone) and `ink-soft` `#4a453d` (8.6:1).
  Trust copy (price, warranty, disclosure, delivery, returns) must meet WCAG
  AA; never low-contrast grey for trust copy.
- `glow` `#e9a23b` is the only saturated accent (the lamp glow). Text-safe on
  charcoal (7.5:1) only; on bone it is ornament, never text.
- No gradients anywhere. Motion is hover/transition only.
- Fonts via `next/font/google`, exposed as CSS variables: Fraunces (display
  serif, Latin), Space Grotesk (grotesque, Latin), Noto Serif TC and
  Noto Sans TC (Chinese). Composition lives in `globals.css`
  (`font-display`, `font-sans`, `font-display-tc`, `font-sans-tc`).

Copy rules: Traditional Chinese and English at equal weight from the first
component (no translation toggle), no em-dashes in user-facing copy.

## Environment

Copy `.env.example` to `.env.local` and fill in:

- `NEXT_PUBLIC_SITE_URL` canonical public site URL (later: canonical, hreflang, sitemap).
- `NEXT_PUBLIC_API_URL` base URL of the Rust API.
- `NEXT_PUBLIC_WHATSAPP_NUMBER` international digits only.
- `NEXT_PUBLIC_GA_MEASUREMENT_ID` GA4 ID, empty disables GA.
- `NEXT_PUBLIC_GSC_VERIFICATION` Search Console token, empty omits the meta tag.

## Catalogue and availability data layer (T2)

- `lib/money.ts` integer-cents money helpers. `formatHKD(cents)` renders
  whole dollars as `HK$1,615` and non-zero cents as `HK$1,234.56`; throws
  `RangeError` on negative or non-integer input. Money is integer cents end
  to end; division happens for display only.
- `lib/catalog.ts` the static opening-drop catalogue (content/catalogue role
  per DATA-01): 8 Louis Poulsen SKUs with bilingual model and colourway
  names, units, integer-cent prices, drop numbers 01-16, heritage and
  verified-facts-only electrical copy, and labelled reference prices
  (TRUST-02: source + checked date; `null` for the PH 1/1 Piano Table, whose
  UI says verification pending). Exports the types, `CATALOG`,
  `getProduct(slug)`, `totalUnits` and `DROP { totalPieces: 16 }`.
- `app/api/availability/route.ts` dynamic route handler (`force-dynamic`):
  the browser-facing availability endpoint. `fetchAvailabilityLive()` reads
  `${NEXT_PUBLIC_API_URL}/api/products` with `cache: "no-store"` and a 10s
  abort timeout; 200 `{ ok: true, availability }` on confirmed data, 503
  `{ ok: false }` on any failure, with a timestamped server-side error log
  (the "discrepancy is reported" leg; full alerting is M3 ops).
- `lib/availability-lifecycle.ts` pure client lifecycle (framework-free,
  fully unit-tested): in-flight-only request dedupe (fulfilled results are
  never retained as dedupe keys), 60s confirmation TTL (`CONFIRMED_TTL_MS`),
  fail-closed on expiry or refresh failure, reconfirm on mount, client-side
  navigation and visibility resume, 10s fetch timeout.
- `components/availability-context.tsx` + `components/stock-badge.tsx`: the
  provider wraps the locale layout and runs one shared session; badges show
  `N left` / sold out / unconfirmed. Only a fresh confirmed count renders.
- Tests: `test/catalog.test.mjs`, `test/availability.test.mjs`,
  `test/availability-route.test.mjs` and
  `test/availability-lifecycle.test.mjs` are unit suites (mocked fetch/clock,
  no network); `test/routes.test.mjs` and `test/pages.test.mjs` are
  server-based behavioural suites.

## Live availability architecture (commitment 5b)

SSR HTML never contains a stock number. Static pages render a bilingual
"confirming availability" placeholder; the client provider fetches
`/api/availability` (which reads the Rust API live, no-store) and badges swap
to a real count only on a fresh confirmation. A displayed count expires after
60 seconds: the badge returns to confirming and reconfirms; if any refresh
fails the count disappears (fail-closed) and the route handler logs the
discrepancy server-side. Time-based ISR was rejected for stock because Next
serves the stale page while revalidating, which can show a number older than
the 60-second bound. On-demand invalidation on stock change and ops alerting
are M3 gaps.

## Scope

T1: locale routing, fonts, design tokens, env template, lint + typecheck.
T2: catalogue + money data layer. T3: editorial homepage, 16 static product
story pages (8 SKUs x 2 locales) with the trust architecture (disclosure,
pending warranty copy, labelled reference pricing, no delivery promises,
verified electrical facts, live stock badge), placeholder art with the
lights on/off toggle, WhatsApp enquiry (env-gated). Not yet: cart/checkout
and payment (M1 money path), GA/GSC wiring, SEO surface (hreflang, JSON-LD,
sitemap; T4), `output: "standalone"` for the Docker deploy.
